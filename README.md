# 7반 학급 운영센터 (V1)

고등학교 학급에서 실제로 사용하는 학급 운영 웹앱입니다. 학생이 로그인해서 공부시간을
사진과 함께 인증하면, 관리자가 승인한 기록만 자동으로 합산되어 주간 랭킹에 반영됩니다.
학급 캘린더, 공지사항, 익명 물품 신청 기능도 함께 제공합니다.

- **프론트/백엔드**: Next.js 16 (App Router, TypeScript, Server Actions)
- **DB / 인증 / 파일 저장**: Supabase (Postgres + RLS, Auth, Storage)
- **배포**: Vercel
- **스타일**: Tailwind CSS v4, Pretendard

---

## 1. Supabase 프로젝트 준비

1. https://supabase.com 에서 새 프로젝트를 만듭니다. (Region: Northeast Asia / Seoul 권장)
2. 좌측 메뉴 **SQL Editor** → New query 에서 `supabase/schema.sql` 파일 전체 내용을
   붙여넣고 **Run** 을 눌러 테이블 · RLS 정책 · Storage 버킷을 한 번에 생성합니다.
3. `supabase/schema.sql` 맨 아래의 `insert into public.roster ...` 부분을
   **우리 반 실제 학번/이름 명단으로 수정**한 뒤 실행하세요. (관리자가 될 사람도 포함해서
   일반 학생과 동일하게 명단에 등록합니다.)
4. **Project Settings → API** 메뉴에서 다음 3개 값을 복사해둡니다.
   - `Project URL` → `NEXT_PUBLIC_SUPABASE_URL`
   - `anon public` 키 → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `service_role` 키 → `SUPABASE_SERVICE_ROLE_KEY` (절대 외부에 공개 금지)

## 2. 로컬에서 실행해보기 (선택)

```bash
npm install
cp .env.example .env.local   # 위에서 복사한 값 3개를 채워 넣기
npm run dev
```

http://localhost:3000 에서 확인할 수 있습니다.

## 3. Vercel 배포

1. 이 프로젝트 폴더를 GitHub 저장소로 올립니다.
2. https://vercel.com 에서 **Add New → Project** 로 그 저장소를 가져옵니다.
   (Framework Preset: Next.js 로 자동 인식됩니다.)
3. **Environment Variables** 에 `.env.example` 의 3개 값을 그대로 등록합니다.
4. **Deploy** 를 누르면 몇 분 안에 실제 URL(`https://프로젝트명.vercel.app`)이 발급됩니다.

## 4. 관리자 계정 만들기

관리자도 처음에는 **일반 학생과 동일하게** `/signup` 에서 학번+이름+비밀번호로 가입합니다.
가입이 끝나면 Supabase **SQL Editor** 에서 아래 SQL 한 줄을 실행해 관리자로 승격하세요.

```sql
update public.profiles set role = 'admin' where student_number = '실제 학번';
```

이후에는 로그인한 관리자가 **관리자 → 학생 관리** 화면에서 다른 사람의 권한도 직접
학생 ↔ 관리자로 바꿀 수 있습니다. (배포 전 반드시 관리자 계정 비밀번호를 안전하게
설정/변경해두세요.)

## 업데이트 내역 (v2) — 반영하려면 `supabase/schema_v2.sql` 실행 필요

기존에 `supabase/schema.sql`을 이미 실행한 프로젝트라면, Supabase SQL Editor에서
**`supabase/schema_v2.sql`을 이어서 한 번 더 실행**하세요. (v1 스키마를 지우지 않고
추가/수정만 하는 마이그레이션이라 안전하게 반복 실행할 수 있습니다.)

- **캘린더 전체 편집 개방**: 이제 로그인한 사용자라면 누구나 일정을 추가/수정/삭제할 수 있어요.
  (역할 변경만은 계속 관리자 전용입니다.)
- **일정 색상**: 일정마다 6가지 색상 중 골라 캘린더에 표시할 수 있어요.
- **날짜 클릭 → 상세 화면**: 그 날의 일정 목록과, 요일별 교시 시간표, 교시별 메모/사진을
  한 화면에서 보고 바로 수정할 수 있어요.
- **개인별 시간표**: 반 전체의 기본 시간표(업로드하신 이미지 기준으로 미리 채워둠)가 있고,
  로그인한 학생은 `/timetable`에서 자기 칸만 자유롭게 바꿀 수 있어요. 기본 시간표 자체는
  관리자만 수정합니다.
- **공휴일 자동 표시**: 2026년 하반기 공휴일(광복절, 추석, 개천절, 한글날, 성탄절 등)이
  미리 등록되어 있고, 주말은 캘린더에서 자동으로 옅게 표시돼요.
- **로그인 없이 보기**: `/schedule` 페이지(로그인 화면의 "로그인 없이 시간표·일정만 보기"
  버튼)에서 기본 시간표와 이번 달 일정을 로그인 없이 볼 수 있어요. 수정은 로그인 후에만
  가능합니다.
- **공지사항도 전체 편집 개방**됩니다.
- **자동 관리자 지정**: 학번 `20703`(김도건), `20714`(손슬아)는 회원가입과 동시에 자동으로
  관리자 권한을 받습니다.
- **인증 사진 업로드 UI**: 아이콘 기반 촬영/선택 버튼으로 더 명확하게 바뀌었고, 업로드 전
  브라우저에서 자동으로 리사이즈·압축해서 저장 용량을 아낍니다 (시간표 메모의 사진도 동일).
- **로그인 유지**: Supabase 세션이 쿠키에 저장되고 매 요청마다 자동 갱신되므로, 한 번
  로그인하면 로그아웃하기 전까지 그 기기/브라우저에서는 계속 로그인 상태가 유지됩니다.
  (IP 기반 자동 로그인은 같은 와이파이를 쓰는 다른 사람이 남의 계정으로 접속될 위험이 있어
  일부러 사용하지 않았습니다.) 세션 유지 기간을 더 늘리고 싶다면 Supabase 대시보드 →
  Authentication → Sessions 에서 조정할 수 있어요.

### 알아두면 좋은 점 (v2 설계 트레이드오프)

캘린더/시간표 메모/공지사항을 전체 학생에게 열어드린 만큼, 나쁜 의도를 가진 사람이 있다면
다른 사람이 쓴 내용을 지우거나 바꿀 수도 있습니다 (반 전체가 서로 신뢰한다는 전제의 설계예요).
문제가 생기면 언제든 다시 관리자 전용으로 좁혀드릴 수 있어요.



학생은 이메일이 아니라 **학번 + 비밀번호**로 로그인합니다. 내부적으로는 학번을
`{학번}@class7.internal` 형태의 전용 이메일로 변환해 Supabase Auth 를 사용하며,
`roster` 테이블에 등록된 학번만 가입할 수 있고 학번당 1계정만 허용됩니다
(중복 가입 시 서버가 차단).

## 업데이트 내역 (v3)

- **v2 스키마 롤백 버그 수정**: `schema_v2.sql` 끝부분의 유니크 제약조건이 조건에 따라
  스크립트 전체를 롤백시킬 수 있었던 버그를 고쳤습니다. **`supabase/schema_v2.sql`을
  다시 한번 실행**해주세요 (몇 번을 실행해도 안전한 멱등 스크립트입니다). 같은 반 학생끼리
  이름/학번을 조회할 수 있도록 `profiles` 조회 권한도 넓혔습니다 (캘린더 메모 작성자 표시 등에 필요).
- **체감 속도 개선**: 시간표·랭킹·물품신청 통계 화면에 TanStack Query를 적용해 캐싱 +
  낙관적 업데이트로 반영, 재방문 시 즉시 뜨고 시간표 편집은 저장 버튼을 눌러도 화면이
  깜빡이지 않습니다. 주요 페이지에 로딩 스켈레톤을 추가해 이동 시 빈 화면 대신 즉시
  레이아웃이 보이도록 했습니다. 계속 쌓이기만 하던 목록(내 인증기록, 관리자 인증목록,
  공지사항)에 조회 개수 제한을 걸어 데이터가 많아져도 느려지지 않게 했습니다.
- **홈 화면에 "오늘 시간표" 카드 추가** — 오늘의 일정 아래에 오늘 몇 교시에 무슨 수업이
  있는지 바로 보여줍니다 (개인 시간표 반영).
- **다크모드**: 기기 설정이 다크모드면 앱도 자동으로 다크 테마로 전환됩니다.
- **에러 처리 개선**: 오류가 나거나 없는 페이지에 접속해도 기술적인 에러 메시지 대신
  디자인에 맞는 안내 화면이 뜨도록 했습니다.
- **앱 아이콘 · manifest 추가**: 홈 화면에 추가하면 "7반" 아이콘과 함께 앱처럼 실행됩니다.

## 업데이트 내역 (v9) — 반영하려면 `supabase/schema_v3.sql` 재실행 필요

물품 신청에 반려 사유 컬럼이 추가되어 **`supabase/schema_v3.sql`을 다시 실행**해야
합니다 (한 줄 추가된 것 외엔 이전과 동일한 파일이라 여러 번 실행해도 안전합니다).

- **CSV 다운로드 버튼에 로딩 표시** — 누르면 "다운로드 중..."으로 바뀌고, 완료되면
  파일이 저장됩니다 (이전엔 클릭해도 아무 반응이 없어 보였어요).
- **물품 신청 반려 시 사유 입력** — 관리자가 상태를 "반려"로 바꾸면 사유를 물어보고,
  학생은 "내 신청 목록" 탭에서 반려 사유를 확인할 수 있어요.
- **시간표 페이지 온보딩 힌트** — 처음 방문 시 "칸을 눌러 나만의 시간표로 바꿀 수 있다"는
  안내가 뜨고, 닫으면 다시 보이지 않아요.
- **로그인/회원가입 유효성 검사 메시지 개선** — 빈 칸, 숫자가 아닌 학번, 짧은 비밀번호 등
  구체적인 안내 문구로 바로 알려줍니다.

## 업데이트 내역 (v10) — PC/모바일 기능 불일치 및 성능 문제 수정

DB 스키마 변경 없음 — 저장소만 교체하면 됩니다.

이번 업데이트는 실제 버그 4개를 찾아 고쳤습니다:

1. **PC(데스크톱)에 네비게이션이 아예 없었던 문제** — 하단 메뉴바가 데스크톱 화면에서는
   숨겨지도록 되어 있었는데, 그 자리를 대신할 메뉴가 없어서 PC에서는 URL을 직접 입력하지
   않는 한 페이지 이동이 불가능했습니다. 상단 고정 네비게이션 바를 새로 추가했습니다.
2. **모바일 캘린더에서 "일정 없는 날"은 눌러 들어갈 수 없었던 문제** — 그래서 그 안에 있는
   교시별 안내사항 편집 기능에도 접근할 수 없었습니다. 미니 월간 달력을 추가해서 일정이
   있든 없든 모든 날짜를 모바일에서도 누를 수 있게 했습니다.
3. **수업이 없는 빈 교시는 안내사항 편집 UI 자체가 안 보였던 문제** — 이제 1~7교시가 항상
   전부 표시되어, 비어있는 교시에도 메모/사진을 추가할 수 있습니다.
4. **관리자가 모바일에서 로그아웃할 방법이 없었던 문제** — 관리자 화면의 로그아웃 버튼이
   데스크톱에서만 보이도록 되어 있던 걸 고쳤습니다.

**성능 최적화**: 사진이 많은 화면(내 인증기록, 관리자 인증목록, 교시별 메모)에서 사진 하나당
서버에 개별 요청을 보내던 것을 한 번의 요청으로 묶었습니다. 사진이 여러 장인 화면일수록
체감 속도가 눈에 띄게 빨라집니다.

## 업데이트 내역 (v11) — 교시별 일정을 핵심 기능으로 전면 재배치

DB 스키마 변경 없음 — 저장소만 교체하면 됩니다.

- **PC에서 관리자 페이지 접근 불가 문제 해결** — 상단 메뉴에 "더보기" 드롭다운을 추가했고,
  관리자 계정으로 로그인하면 그 안에 "관리자 페이지" 링크가 보입니다.
- **홈 화면 최상단에 교시별 일정 배치** — 로그인하면 접속하자마자 오늘(또는 선택한 날짜)의
  1~7교시 수업과 메모를 바로 볼 수 있어요. 최근 7일 날짜 스트립으로 다른 날도 한 번에
  이동할 수 있고, 메모가 있는 날짜엔 "메모 N개" 배지가 붙습니다.
- **로그인 없이도 교시별 일정 열람 가능** — `/schedule` 페이지가 이제 주간 시간표 나열이
  아니라 실제 그날의 교시별 수업+메모를 바로 보여줍니다. 날짜 선택기와 전날/다음날
  이동으로 원하는 날짜를 자유롭게 넘나들 수 있어요 (미래 날짜 포함).
- **캘린더 날짜 목록에 메모 개수 표시** — PC 월간 그리드, 모바일 미니 달력, 모바일 목록
  전부에 "메모 N개"가 보여서 일정 추가 여부와 별개로 메모가 있는지 한눈에 파악할 수
  있습니다. 메모만 있고 캘린더 일정은 없는 날짜도 이제 목록에 노출됩니다.
- **날짜 선택기(달력 아이콘) 추가** — 홈, 캘린더, 캘린더 상세, 공개 일정 페이지 전부에
  날짜를 직접 골라 미래 날짜까지 이동할 수 있는 입력창이 생겼습니다.
- 교시 카드에 메모 개수 배지를 추가해 일정 추가 폼과 교시별 메모가 시각적으로 더
  잘 구분되도록 다듬었습니다.

## 주요 기능 (V1 구현 범위)

| 기능 | 학생 | 관리자 |
|---|---|---|
| 공부시간 인증 (사진, 몰아서 여러 건 제출) | 제출 | 승인/반려/시간 수정 |
| 주간 랭킹 (월~일, Asia/Seoul 자동 계산) | 조회 (실명/가림/학번/닉네임 중 관리자가 설정한 방식으로 표시) | 표시 방식 설정 |
| 학급 캘린더 (시험/수행/숙제/준비물 등) | 조회 (PC 월간 그리드 / 모바일 날짜별 리스트) | 추가/삭제 |
| 공지사항 | 조회 | 작성/삭제, 중요 공지 강조 |
| 익명 물품 신청 | 신청 + 익명 통계 조회 | 상태 변경 (익명 유지) |
| 학생/관리자 권한 관리 | - | 명단 등록, 역할 변경 |
| CSV 내보내기 | - | 공부시간 / 랭킹 / 물품신청 |
| 감사 로그 (audit log) | - | 인증 승인·반려·수정, 역할 변경 등 자동 기록 |

**V1 범위 밖 (구조상 확장 가능하도록만 설계)**: 성적 향상 인증, 보상/상품 시스템,
설문조사, 자동 승인 모드, 인앱 알림, 다크모드 UI. 스키마와 코드 구조는 이후에 이
기능들을 추가하기 쉽게 (예: `study_sessions.status`, `audit_logs`, role 확장 등)
설계되어 있습니다.

## 보안 설계 요약

- 모든 테이블에 **Row Level Security** 적용 — 학생은 자기 데이터만, 관리자는 전체
  접근 가능하도록 DB 레벨에서 강제 (프론트엔드 코드가 아니라 Postgres 정책이 실제 방어선).
- 관리자 페이지/서버 액션/API 라우트 진입 시마다 `requireAdmin()` 으로 서버에서
  role 을 다시 확인 — URL을 직접 입력해도 우회 불가.
- 인증 사진은 비공개 Storage 버킷에 저장되고, 본인 또는 관리자만 서명 URL로 열람 가능.
- 익명 물품 신청은 작성자 id 를 DB에는 보관하되(악용 방지), 화면에는 어디에도 노출하지 않음.
- 미래 날짜 인증·음수/24시간 초과 공부시간은 DB 제약조건(check)으로 원천 차단.
- 같은 학생·같은 날짜 시간대 중복은 자동 삭제하지 않고 관리자 화면에 "시간 중복 의심"
  배지로 표시해 관리자가 직접 판단.

## 알려진 제약 / 다음에 할 일

- 관리자가 자기 자신의 권한을 학생으로 낮추는 것을 막는 안전장치는 아직 없습니다
  (관리자가 1명뿐인 반은 주의해서 사용하세요).
- 자동 승인 모드, 성적 향상, 보상 시스템은 스키마상 자리는 마련해두었지만 V1에는
  포함하지 않았습니다.
- 이미지 파일 크기/형식 검증은 브라우저의 accept="image/*" 수준이며, 서버 측
  용량 제한을 더 엄격히 걸고 싶다면 Supabase Storage 버킷 설정에서 최대 파일 크기를
  지정하세요 (Dashboard → Storage → study-photos → Configuration).
