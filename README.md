# 7반 학급 운영센터 (V1)

고등학교 학급에서 실제로 사용하는 학급 운영 웹앱입니다. 학생이 로그인해서 공부시간을
사진과 함께 인증하면, 관리자가 승인한 기록만 자동으로 합산되어 주간 랭킹에 반영됩니다.
학급 캘린더, 공지사항, 익명 물품 신청 기능도 함께 제공합니다.

- **프론트/백엔드**: Next.js 16 (App Router, TypeScript, Server Actions)
- **DB / 인증 / 파일 저장**: Supabase (Postgres + RLS, Auth, Storage)
- **배포**: Vercel
- **스타일**: Tailwind CSS v4, Pretendard

---

## 1. Supabase 프로젝트 준비

1. https://supabase.com 에서 새 프로젝트를 만듭니다. (Region: Northeast Asia / Seoul 권장)
2. 좌측 메뉴 **SQL Editor** → New query 에서 `supabase/schema.sql` 파일 전체 내용을
   붙여넣고 **Run** 을 눌러 테이블 · RLS 정책 · Storage 버킷을 한 번에 생성합니다.
3. `supabase/schema.sql` 맨 아래의 `insert into public.roster ...` 부분을
   **우리 반 실제 학번/이름 명단으로 수정**한 뒤 실행하세요. (관리자가 될 사람도 포함해서
   일반 학생과 동일하게 명단에 등록합니다.)
4. **Project Settings → API** 메뉴에서 다음 3개 값을 복사해둡니다.
   - `Project URL` → `NEXT_PUBLIC_SUPABASE_URL`
   - `anon public` 키 → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `service_role` 키 → `SUPABASE_SERVICE_ROLE_KEY` (절대 외부에 공개 금지)

## 2. 로컬에서 실행해보기 (선택)

```bash
npm install
cp .env.example .env.local   # 위에서 복사한 값 3개를 채워 넣기
npm run dev
```

http://localhost:3000 에서 확인할 수 있습니다.

## 3. Vercel 배포

1. 이 프로젝트 폴더를 GitHub 저장소로 올립니다.
2. https://vercel.com 에서 **Add New → Project** 로 그 저장소를 가져옵니다.
   (Framework Preset: Next.js 로 자동 인식됩니다.)
3. **Environment Variables** 에 `.env.example` 의 3개 값을 그대로 등록합니다.
4. **Deploy** 를 누르면 몇 분 안에 실제 URL(`https://프로젝트명.vercel.app`)이 발급됩니다.

## 4. 관리자 계정 만들기

관리자도 처음에는 **일반 학생과 동일하게** `/signup` 에서 학번+이름+비밀번호로 가입합니다.
가입이 끝나면 Supabase **SQL Editor** 에서 아래 SQL 한 줄을 실행해 관리자로 승격하세요.

```sql
update public.profiles set role = 'admin' where student_number = '실제 학번';
```

이후에는 로그인한 관리자가 **관리자 → 학생 관리** 화면에서 다른 사람의 권한도 직접
학생 ↔ 관리자로 바꿀 수 있습니다. (배포 전 반드시 관리자 계정 비밀번호를 안전하게
설정/변경해두세요.)

| 기능 | 학생(로그인) | 비로그인 | 관리자 |
|---|---|---|---|

| 학급 캘린더 (색상, 카테고리 아이콘, 다중 삭제) | 조회 + 편집 | 조회만 | 조회 + 편집 |
| 개인 시간표 (기본 템플릿 + 개인화) | 조회 + 본인 것만 편집 | 기본 템플릿만 조회 | 기본 템플릿 편집 |

| 이미지 클릭 확대보기 | 전체 이미지 적용 | 전체 이미지 적용 | 전체 이미지 적용 |

**로그인 계정**은 캘린더/공지/시간표 등 "모두에게 열린" 콘텐츠 편집 권한을 가지며,
**관리자 역할 변경만은 관리자 전용**으로 남아있습니다. 학번 20703(김도건)·20714(손슬아)는
가입 즉시 자동으로 관리자가 됩니다.

**V1 범위 밖** (스키마·구조는 확장 가능하게 설계, 기능은 미구현): 성적 향상 인증,
보상/상품 시스템, 설문조사, 자동 승인 모드, 인앱 알림.

## 보안 설계 요약

- 모든 테이블(10개)에 **Row Level Security** 적용 — 학생은 자기 데이터만, 관리자는
  전체 접근 가능하도록 DB 레벨에서 강제. 프론트엔드가 아니라 Postgres 정책이 실제 방어선.
- 관리자 페이지는 레이아웃에서 일괄 보호되고, 모든 관리자 전용 Server Action은
  **개별적으로도** `requireAdmin()`을 재검증합니다 (URL 우회·직접 호출 모두 차단).
- "모두에게 열린" 캘린더/공지/시간표 편집도 최소한 **로그인은 필수**(`requireProfile()`)이며,
  개인 시간표만은 본인 것만 수정 가능하도록 별도로 제한되어 있습니다.
- `SUPABASE_SERVICE_ROLE_KEY`는 서버 전용 파일에서만 참조되며 클라이언트 번들에
  포함되지 않는 것을 확인했습니다.
- 인증 사진(study-photos)은 본인 또는 관리자만 열람 가능한 비공개 버킷,
  교시별 메모 사진(class-photos)은 로그인한 학급 구성원 전체가 열람 가능한 비공개 버킷입니다.
- 익명 물품 신청은 작성자 id를 DB에는 보관하되(악용 방지), 화면에는 노출하지 않습니다.
- 미래 날짜 인증·음수/24시간 초과 공부시간은 DB 제약조건으로 원천 차단됩니다.

## 알려진 제약 / 다음에 할 일

- **속도는 Supabase 프로젝트 리전에 좌우됩니다.** `vercel.json`에 서울(`icn1`)로
  설정해뒀지만, Supabase 프로젝트가 다른 리전에 있으면 오히려 의미가 없습니다.
  Supabase 대시보드 → Project Settings → General → Region을 확인하세요.
- 비로그인 상태(`/schedule`)에서는 교시별 메모의 **사진은 보이지 않을 수 있습니다**
  (class-photos 버킷이 로그인 사용자에게만 열람 권한이 있어서 의도된 동작입니다 —
  텍스트 메모는 정상적으로 보입니다). 비로그인 사용자에게도 사진을 보여주고 싶다면
  요청해주세요.
- 관리자가 본인 권한을 스스로 학생으로 낮추는 걸 막는 안전장치는 없습니다
  (관리자가 1명뿐인 반은 주의).
- 이미지 크기/형식 검증은 브라우저 `accept="image/*"` 수준입니다. 서버 측 용량 제한을
  더 엄격히 걸고 싶다면 Supabase Storage 버킷 설정에서 지정하세요
  (Dashboard → Storage → 버킷 → Configuration).
